## 研究背景

终端智能体的表现同时取决于模型与外围执行系统。通用 harness 让模型自行调用命令、查看输出和停止；更复杂的 harness 则可以保存流程状态，或者在失败后要求继续检查。它们不仅改变推理时的成绩，也改变模型能够产生什么训练经验。

因此，一个自然想法是：让同一模型在多种 harness 下解决问题，把成功轨迹集中起来做监督微调。然而，轨迹中既包含模型学会的解题过程，也包含外部控制器提供的支持。直接模仿整段记录，未必能把支持撤掉后仍然需要的能力学进去。本文把 harness 当作经验发现工具，研究怎样把这些经验转化为通用接口下的训练数据。[§1–2](https://arxiv.org/pdf/2610.02826v1#page=2)

## 问题与挑战

困难在于**成功是模型与控制器共同产生的，训练目标却是撤去特殊控制器后的模型**。例如，StateM 帮助智能体维护阶段状态，RSRT 在验证失败后推动它继续工作；直接删掉这些提示，剩余动作未必仍是连贯、可独立执行的示范。

另一方面，从成功轨迹提炼的指导也可能泄漏最终补丁、隐藏测试或无法从环境推导的答案。重写必须保留程序性经验，同时避免把“照抄答案”伪装成重新解题。因此，文本改写不够，还需要真正从干净环境执行一次，并验证结果。

## 核心发现 Finding

**作者的核心观点：不同 harness 可以发现互补的成功经验，而这些经验可以通过重新实践，转换为同一通用 harness 下可学习的行为。**

我的理解是，关键不在于让模型记住外部控制器说过什么，而在于把控制器促成的检查、恢复和推进步骤重新落实到模型自己的动作中。逻辑链是：多种运行方式扩大可解任务覆盖 → 从成功中提炼程序性指导 → 在通用接口下重新解决 → 将经过验证的公开执行记录用于训练。

例如，源轨迹依靠状态机提醒才检查依赖版本。重写后的执行者可以自行读取依赖文件、安装正确版本并运行检查，而无需学会源状态机的专用命令。这是机制解释示例；具体证据来自论文的覆盖实验和重执行案例，并不证明每项能力都已独立内化。

## 方法

### 1. 用多种 harness 发现成功

全流程使用同一 Qwen-3.8-27B。任务池包含 2,509 个自建 SWR 任务及 420 个筛选、修改后的 RST 任务，共 2,929 个，覆盖软件、科学、硬件等领域。

三种发现方式分别是 Terminus 2 的通用动作—观察循环、StateM 的显式状态与阶段检查，以及 RSRT 的失败后反思续跑。RSRT 每次声称完成后运行验证器，只反馈通过或失败，不暴露测试内部；单题发现预算最多 180 分钟。续跑保留原对话和沙箱状态，这与后续从新沙箱开始的重写不同。

### 2. Planner 提炼 runbook，Critic 检查泄漏

先压缩源轨迹，保留任务、动作和环境观察，移除特殊控制消息。Planner 生成目标、里程碑、检查、恢复方式及常见陷阱组成的 runbook。规则检查排除格式错误和不支持的工具，模型 Critic 仅看到公开任务与 runbook，判断它是否泄漏答案、验证器信息或不适用于目标接口的内容；不合格则带着反馈重新生成，受重试预算限制。

### 3. Executor 在通用 harness 下重新执行

每条源成功轨迹采样 4 个候选 runbook，每个通过审查的 runbook 指导 4 次独立执行，温度 0.7。执行发生在新沙箱中，使用 Terminus 2。runbook 是生成期的私有指导，最终训练记录不包含它，也不包含 Critic 对话。

只有通过任务验证和轨迹审查的记录才保留；额外审查会查找无法由任务或环境推导的值，降低暗中转移答案的风险。论文报告 12,893 次重写 rollout，其中保留 11,094 条通过的重写轨迹。训练还加入 766 条未重写的 Terminus 2 成功轨迹。[§2、§3.4–3.5](https://arxiv.org/pdf/2610.02826v1#page=4)

### 4. 微调后撤去私有指导

Base 是原始模型；Direct SFT 使用去除特殊插入内容后的源成功轨迹；RSR 使用验证后的重写数据及上述通用 harness 源轨迹。部署时只保留通用 harness，不提供发现阶段的特殊控制器或 runbook。这里的“递归”主要对应规划与批评的重试，不应扩张成已验证的无限模型—harness 自进化闭环。

## 实验与结论

### 互补性：是否只是多采样带来的覆盖增长？

全记录池中，最佳单一 harness 解出 565 个任务，三者并集为 759 个，增加 194 个，即相对提升 34.3%。但各 harness 的 rollout 数不同，因此作者另外取 1,247 个采样次数相等的任务：每种 harness 均有 2,074 次 rollout，最佳单一方式解出 285 个，三者并集解出 352 个，相对增加 23.5%。

该对照说明互补性在相同的**每种 harness 采样次数**下仍存在；三种方法的并集仍消耗更多总执行，不能解读为相同总算力下必然优于单一 harness。

### 训练效果：重写数据是否比直接训练有效？

表 5 的 pass@3 是三次尝试内至少成功一次；不是单次成功率。

| 基准 | Base | Direct SFT | RSR |
|---|---:|---:|---:|
| Terminal-Bench 2 | 57.0% | 53.4% | 74.2% |
| Terminal-Bench 3 | 0.0% | 5.4% | 9.5% |
| Terminal-Bench 4 | 1.5% | 4.5% | 9.1% |
| 自建 TB Hard | 39.0% | 56.0% | 63.0% |
| 自建 SWR100 | 3.0% | 3.0% | 6.0% |

最有解释力的例子是 TB2：Direct SFT 相比 Base 退步 3.6 个百分点，RSR 则比 Direct SFT 高 20.8 个百分点。三次运行的平均单次成功率也从 Base 的 51.7%、Direct SFT 的 43.8% 提升至 70.1%，所以提升不只出现在 pass@3。作者观察到直接训练模型的一些轨迹会反复执行无进展动作，但检查三个案例不足以估计整体失败机制的频率。

LHTB 的过程奖励从 0.21、0.25 升至 0.29；**三组都没有完整解决 46 个任务中的任何一个**，应解释为部分进展改善。[表 5，§3.6](https://arxiv.org/pdf/2610.02826v1#page=11)

### 代表案例：同一份指导不保证成功

Markdown 解析任务的 12 次重写中仅 7 次通过，成功重写的中位轮数由源轨迹的 64 降至 32。OpenFOAM 案例的 8 次重写中 7 次通过，中位成功轮数由 38 降至 29。它们说明程序性指导可以减少摸索并保留分析、修复行为，也说明必须验证实际执行结果，不能只凭计划完整或轨迹短就判断质量。

### 局限与可支持的结论

数据规模扩张、接口标准化和质量筛选一起变化，主表没有等训练数据量地隔离每个因素，因此不能声称收益全部来自重写本身。训练超参数与完整预算披露也不足以直接复现全部成本。§3.4 报告重写覆盖 975 个独立任务，而前面共同发现池仅有 759 个成功任务；两者统计范围如何衔接没有充分交代，应核对数据而非自行解释。模型自身担任 Critic 也不保证完全消除泄漏。

可以得出的结论是：在所报告的模型和终端基准上，这套“发现—重新执行—验证—训练”流程优于直接训练源轨迹；它为将 harness 支持转换成模型能力提供了一条可行路线。

## 关键术语

- **Harness（执行框架）**：控制信息、工具、状态与停止规则的外围系统。例子：失败后要求继续检查的 RSRT。
- **Runbook（操作指南）**：描述步骤、检查与恢复方式的程序性指导。例子：先确认依赖版本，再构建和测试，而非提供最终补丁。
- **Trajectory rewriting（轨迹重写）**：利用经验指导新的真实执行。例子：新沙箱内重新调用工具，而非改写旧对话措辞。
- **Solution leakage（答案泄漏）**：指导直接提供本应由执行者求得的内容。例子：未读取环境便获知隐藏目标值。
- **Pass@3（三次尝试成功率）**：三次执行中至少一次通过的任务比例。例子：某题仅第三次成功，仍计入 pass@3。

## 后续阅读与实践

复现时应先做等数据量、等训练 token 的 Direct SFT 与 RSR 对照，再分别移除 Critic、重执行及多 harness 发现。需要同时保存任务 ID、源轨迹、runbook 与公开轨迹的映射，以核查 759/975 的统计范围及泄漏审查。[模型权重](https://huggingface.co/IntelligenceLab/RSR-27B)与[论文全文](https://arxiv.org/pdf/2610.02826v1)可作为入口。
