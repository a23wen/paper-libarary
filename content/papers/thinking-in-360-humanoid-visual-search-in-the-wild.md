## 📋 论文概述

这篇论文问了一个很直观、但现有多模态模型很少被系统测试的问题：**当目标不在当前视野里时，模型能否像人一样主动转头，一边观察、一边推理，直到找到目标物体或正确路径？**

传统视觉搜索通常把完整静态图片交给模型，模型可以在同一张二维画布上裁剪、放大或选区域。真实世界却不是这样：人在拥挤地铁站寻找 7 号出口时，最初可能只看到墙壁和一块指示牌；必须转头看到新区域，解释箭头与楼层关系，再决定继续探索还是提交方向。感知和动作形成闭环，错误转头会改变之后能看到什么。

作者据此提出 **Humanoid Visual Search（HVS，人形视觉搜索）**，并把全身导航中“停下来观察和决定方向”的关键时刻抽象成头部旋转。环境由一张高分辨率 360° 全景图充当轻量模拟器，agent 每一步只看到一个窄视野透视图，可输出：

- `Rotate(Δφ, Δγ)`：改变头部水平和垂直朝向，取得新的观察；
- `Submit`：认为当前朝向已经对准目标并结束搜索。

任务分成两类：

1. **Humanoid Object Search（HOS）**：找到并把目标物体对准视野中央，模拟抓取前的目标注视；
2. **Humanoid Path Search（HPS）**：找到通往目的地的可行方向，模拟行走前的高层路径决策。

为了评测这两种能力，作者构建 **H* Bench**。它不只包含家庭房间，而是覆盖交通枢纽、大型零售空间、城市街道和公共机构等拥挤真实场景。实验表明，强闭源模型在两项任务上也只有约 30% 成功率。对 Qwen2.5-VL-3B 进行 SFT 和多轮 GRPO 后，物体搜索从 14.83% 提升到 47.38%，路径搜索从 6.44% 提升到 24.94%。

不过，论文最值得注意的不是“RL 让模型涨了多少”，而是增益的结构：**SFT 教会模型基本的观察—转头—提交行为；RL 主要优化角度控制和探索策略，却没有可靠地产生复杂路径推理，而且会在部分困难路径上降低性能。**

## 🎯 研究背景

### 从静态视觉搜索到主动视觉

视觉搜索研究关心如何在复杂画面中找到特定目标。早期方法依赖显著性、上下文和人工搜索策略；近期 V*、Chain-of-Focus 一类方法让 MLLM 利用世界知识，通过裁剪、放大或区域选择逐步找目标。

这些方法仍有两个根本限制：

- **Non-interactive（非交互）**：所有信息本来就在同一张图片里，操作不会发现初始画布之外的新世界；
- **Disembodied（非具身）**：裁剪和放大是文件操作，不是物理动作，模型不需要理解“向右转头之后会看到什么”。

HVS 将搜索改为主动感知：当前动作决定下一帧观察。这样，模型不仅要识别画面，还要管理未知空间。

### 从视觉导航中抽取“关键决策点”

完整视觉导航通常需要连续移动、建图、避障和长轨迹规划，也依赖昂贵的三维模拟器或机器人硬件。作者观察到，人并非在导航的每一时刻都进行高强度推理，而是常在路口、入口、楼梯等关键点停下来搜索线索并确定方向。

因此，论文不模拟整段行走，而只保留关键点上的头部旋转。这种抽象降低了环境建设成本，使真实 360° 视频能变成可重复的闭环环境；与此同时，它仍然保留了动作改变观察这一主动感知要素。

### 头—眼协同的计算抽象

神经科学中，人的头部运动更偏向探索尚未看到的区域，眼动则在当前视野内利用细节。论文没有真正模拟眼球动力学，而是用两个计算尺度近似这个分工：

- `Rotate` 对应头部探索，打开新的全景区域；
- MLLM 对当前透视图的细粒度理解对应视野内利用。

这是一种任务抽象，而不是完整的人体感知模型。

## ⚠️ 问题与挑战

论文的目标是：**让只看到局部视野的 MLLM 在真实、拥挤的 360° 场景中，通过有限次主动旋转，找到目标物体或可行路径并准确提交方向。**

### 1. 因为观察是局部的，所以模型必须管理“未知”而不只是识别“已知”

如果目标不在第一帧里，模型不能仅回答“没有看到”。它要选择一个能最大化新信息的旋转角度。连续做小角度旋转可能反复看到同一区域；过大的随机旋转又会错过线索。

例如寻找超市里的锅具时，合理策略可能是先进行大角度转头发现新货架，再根据类别标识细调角度，而不是每次只向右转 10°。

### 2. 因为识别目标和控制动作是两种能力，所以“看见”不等于“对准”

模型可能正确说出画面里有 Pet Shop，却无法把目标移到中央容差区域，或者在粗略看见目标后过早提交。HOS 因此同时测视觉 grounding 和 perception-action alignment。

### 3. 因为路径不是目标的直线方向，所以 HPS 需要物理和社会空间常识

路径搜索不能只朝目标所在方向走。玻璃墙、柜台、楼层落差都可能阻断直线；楼梯、电梯、走廊和门才构成可行路径。此外，机场入口、斑马线、警戒线和员工区域还包含社会规范。

因此模型即使读懂“Gate B →”也可能：

- 把箭头翻译成错误旋转；
- 试图穿墙或直接跨越高差；
- 忽略应该使用楼梯连接楼层；
- 选择物理可行但违反公共空间规范的路线。

这解释了为什么物体搜索的后训练收益很大，而路径搜索上限明显更低。

### 4. 因为终局成功奖励稀疏，所以 RL 容易优化代理目标

如果只有提交方向落入容差范围才算成功，大部分长轨迹都只得到失败奖励。加入距离奖励似乎能提供更密集信号，但“最终方向离目标近”不等于“找到可行路径”。模型可能学会朝目标直线靠近，却忽略障碍和社会规则。

论文的困难 HPS 子集正显示了这种错位：简单奖励能提高容易样本，却常损害真正需要路径推理的样本。

## 🔍 核心发现 Finding

### 作者明确声称

作者认为，**一张 360° 全景图足以在不依赖真实机器人或完整三维模拟器的情况下，保留头部转动造成的感知—动作闭环，从而可扩展地研究真实场景中的具身视觉搜索。**

实验进一步揭示：MLLM 从互联网图文数据学到的静态视觉搜索能力，不能直接迁移为主动具身搜索能力。Mini-o3 和 Chain-of-Focus 在静态 V* Bench 上约为 88%，但在 H* Bench 上分别只有 2.5% 和 11.6%。

### 我的理解

我认为这篇论文真正的新视角是：**把完整导航拆成若干“必须先转头弄清楚再行动”的信息决策点，能以很低的环境成本隔离并测量具身系统中的主动观察能力。**

它改变了基准设计的单位：

```text
完整导航：移动 + 建图 + 避障 + 定位 + 搜索 + 路径规划

HVS：局部观察 → 解释线索 → 选择头部旋转 → 新观察 → 提交方向
```

这样做的价值，是当 agent 失败时，可以更明确地问：它是没看见目标、看见却没对准、不会探索未知区域，还是无法把标识和空间常识转换成行动？

但这一 Finding 也有边界：360° 全景提供的是同一相机中心附近的旋转视图，没有平移、视差、动态物体交互或真实机器人动力学。因此它测到的是 **embodied search 的一个关键原子能力**，而不是完整的三维具身导航。

### 第二个实验性发现：后训练更容易教会感知—运动技能，而不是高阶空间推理

这一点主要由结果结构支持：

```text
Qwen2.5-VL-3B base → SFT → SFT+RL

HOS: 14.83 → 40.83 → 47.38
HPS:  6.44 → 23.00 → 24.94
```

SFT 已贡献大多数增益；RL 对 HOS 额外提升 6.55 点，对 HPS 只提升 1.94 点，并使 HPS Medium 从 23.03 降到 20.18、Extreme 从 14.81 降到 12.04。

换句话说，示范数据可以较有效地教模型“没看到就转头、发现目标后细调、遵循显式箭头”；但面对线索与真实可行方向冲突的情况，简单的 GRPO 奖励没有稳定教会模型物理与社会空间常识。

## 🔬 方法

### 1. 用 360° 全景构造闭环环境

环境是一张高分辨率全景图。任意观察由水平角 `φ` 和俯仰角 `γ` 决定：

```text
o_(φ,γ) = 从全景图在朝向 (φ,γ) 渲染出的窄 FoV 透视图
```

agent 的目标是在语言指令 `x` 和当前观察下，找到最大化任务成功概率的方向。每次旋转后，环境按照新角度渲染下一张透视图，形成多轮历史：

```text
H_t = {(observation_i, reasoning_i, action_i)} for i < t
```

策略在每一步生成文本推理与动作，最多搜索 10 步；未在限制内提交的 episode 记为失败。

### 2. 定义 HOS 与 HPS

**HOS** 的标注是目标 bounding box 中心对应的球面方向 `(φ*, γ*)`。提交方向落在以目标框和固定角容差共同定义的区域内即成功。论文使用水平 30°、垂直 20° 的最低容差，以近似中央注视区域。

**HPS** 只评估水平朝向 `φ*`，固定容差为 10°，因为它要求更精确地对齐运动方向。这里的 ground truth 是标注者认为通向目的地的路径方向，而不是目标物体自身的方位。

### 3. 构建 H* Bench 与训练数据

数据来自自采和公开的高分辨率 360° 视频，最高达到 7680×3840，覆盖 12 个国家、6 个大类和 18 个细分场景。总体约有 3,000 个任务实例；每个实例设置 4 个初始朝向，因此形成约 12,000 个搜索 episode。

正式 benchmark 保留 1,000 个实例：600 个 HOS、400 个 HPS，对应 4,000 个评测 episode。其余实例用于 SFT 或 RL，三者互斥。

标注流程是：

1. 标注者在可旋转透视界面中检查全景；
2. 写出具身搜索指令；
3. 用紧致框标出目标及最优方向；
4. 将框反投影回全景坐标；
5. 为 SFT 轨迹提供每一步的最优动作；
6. GPT-4o 生成观察相关的简短 CoT，人工再检查和修订。

论文报告 6 名标注者投入约 250 小时，最终得到 2,000 条经过人工修订的多轮轨迹。需要注意，正文将这些轨迹作为冷启动数据；附录又说明 SFT 随机抽取 HOS/HPS 各 250 个 instance。这里的“trajectory/episode/instance”统计口径不同，复现时应以开源数据划分为准。

### 4. 第一阶段：SFT 建立行为先验

基础模型是 Qwen2.5-VL-3B-Instruct。作者进行 3 epoch 全参数 SFT，让模型模仿人工动作和经人工修订的推理轨迹。SFT 的作用不是学一个新视觉编码器，而是把已有视觉语言能力组织成结构化的多轮搜索行为。

直观上，SFT 教会模型：

- 当前看不到目标时不要立即提交；
- 旋转后根据新观察更新判断；
- 输出符合工具协议的 `Rotate` 或 `Submit`；
- 在已经接近目标时进行更细的角度修正。

### 5. 第二阶段：多轮 GRPO 优化搜索策略

作者使用 VAGEN 框架进行 70 steps GRPO。每个任务采样一组完整多轮轨迹，用组内 reward 均值和标准差计算 relative advantage，再对整条输出 token 序列更新策略。

基本规则奖励为：

```text
r = r_correctness + r_format

r_correctness = 0.5 if final submission succeeds else 0
r_format      = 0.5 if output follows required tags else 0
```

HPS 还实验了 distance-to-goal reward，但消融结果显示它没有解决困难路径推理。训练设置包括 batch size 32、actor learning rate `1e-7`、KL 系数 `0.01`、temperature 0.7，并在 8×H100 上进行。推理时 temperature 为 0，最多保留 5 张透视图和最近 5 轮对话。

## 📊 实验与结论

### 主结果：当前强模型仍不擅长 HVS

| 模型 | HOS 成功率 | HPS 成功率 |
|---|---:|---:|
| Qwen2.5-VL-3B-Instruct | 14.83 | 6.44 |
| Gemma-3-4B-it | 17.13 | 14.44 |
| GPT-4o | 19.75 | 23.69 |
| Gemini 2.5 Pro | 31.96 | **33.00** |
| HVS-3B（仅 SFT） | 40.83 | 23.00 |
| HVS-3B（SFT+RL） | **47.38** | 24.94 |

HVS-3B 在 HOS 上超过 Gemini 2.5 Pro，说明小模型在专门任务上可以通过行为数据获得强定位和控制能力。但在 HPS 上仍落后，说明结果不能概括为“小模型已获得更强的通用具身智能”。

另一个有意思的结果是，模型更大不保证更好：Qwen2.5-VL-3B 的 HOS 高于 7B，Gemma-3-4B 也高于 12B。这提示 H* Bench 测到的并非单纯的静态知识规模，而包含工具协议、探索策略和动作校准。

### 代表性实验：为何简单路径 reward 会失败

作者在 HPS 上比较三种 GRPO reward：

| 设置 | Overall | Easy | Medium | Hard | Extreme |
|---|---:|---:|---:|---:|---:|
| SFT baseline | **23.44** | 26.00 | **24.56** | **24.77** | **12.50** |
| format + correctness | 22.38 | 33.80 | 17.32 | 21.73 | 7.87 |
| format + correctness + distance | 21.37 | **34.40** | 15.13 | 20.09 | 6.94 |
| format + distance | 21.31 | 29.80 | 17.54 | 20.56 | 11.11 |

所有 RL 变体都提高 Easy，却降低 Overall 和更困难子集。具体例子是：在容易任务中，明显箭头或可见入口通常与正确方向一致，“向目标靠近”是有效信号；在困难任务中，目标方向可能隔着墙或处于另一楼层，距离奖励反而鼓励直线捷径。

因此，论文关于 reward hacking 的表述是作者的解释而非被直接证明的机制。数据明确证明的是 **现有 reward 与困难子集性能不一致**；要确认模型具体利用了什么漏洞，还需要轨迹级策略分析或受控反事实实验。

### HOS 与 HPS 有互补迁移，但不是同一种能力

单独训练 HOS 可把 HPS 从 6.4% 提升到 20.7%，单独训练 HPS 可把 HOS 从 14.8% 提升到 29.5%。前者说明视觉定位和主动探索可迁移到路径任务，后者说明路径训练获得的探索行为也帮助找物体。

但 easy HPS 上，HOS 训练模型达到 37.8%，甚至超过专门的 HPS 模型 33.8%。作者推测这些样本其实退化为“找到清晰视觉线索”，并不需要真正的路径推理。这提醒我们：HPS 总分混合了目标/标志定位和可行路径推断两种难度不同的能力。

### 主动窄视野优于直接输入完整全景

作者用 Gemma-3-4B-it 比较主动旋转和一次性分析完整全景，主动方式更好。合理解释包括：

- 完整 equirectangular panorama 有严重几何扭曲，与模型预训练图像分布不同；
- 局部透视图保留正常视觉尺度；
- 多轮主动观察把高分辨率场景分解成模型能处理的局部证据。

因此，这一实验同时混合了“主动策略的价值”和“输入表示更符合预训练分布”的优势，不能只归因于类人搜索策略。

## 🧩 误差类型

### HOS

1. **Limited visual grounding**：目标藏在拥挤货架或复杂背景中，模型没有可靠识别；
2. **Perception-action gap**：模型已经看见目标，却无法通过细粒度旋转把它对准中央。

### HPS

1. **Vision-action mismatch**：读懂箭头或标志，却输出相反或不精确的旋转；
2. **Lack of physical commonsense**：穿墙、忽略障碍、误解楼层连接或选择会跌落的方向；
3. **Lack of socio-spatial commonsense**：忽略斑马线、员工区域、排队规则和公共空间功能布局。

这五类错误给出了比单一成功率更有用的研究分解：下一代方法可能需要分别改进视觉 grounding、动作校准、可行性建模和社会规范理解。

## ⚠️ 局限与批判性理解

### 1. 全景旋转不等于完整三维具身环境

agent 在固定观察中心旋转，没有真实平移、遮挡变化、碰撞、动力学或执行误差。论文把它描述为硬件无关的 embodied visual search 平台是合理的，但不能据此推断模型已能在真实机器人上完成导航或操作。

### 2. HPS 的标注和指标压缩了多条可行路径

HPS 最终只提交一个水平角度，并围绕标注方向以 ±10° 判断成功。真实场景可能存在多条安全可行路线，或需要先向一个中间方向绕行。单方向 ground truth 可能把合理替代路径判错，也无法评估提交后的整段轨迹是否真的可达目的地。

### 3. benchmark episode 并非完全独立场景

约 3,000 个实例通过 4 个起始方向扩展为约 12,000 个 episode。数量扩大了视角覆盖，却没有等量增加独立环境和任务语义。比较数据规模时应以 instance、panorama 和 episode 三个层次分别报告。

### 4. 地理覆盖广不等于分布公平

数据覆盖 12 个国家和多种语言/建筑风格，这是优点；但来源包含自采、YouTube 和已有数据集，场景频率、相机位置、标识可读性与许可条件可能不均衡。论文没有给出足以判断跨地区公平性的细分性能。

### 5. 推理 CoT 部分由 GPT-4o 生成

SFT 的动作来自人工最优标注，理由由 GPT-4o 生成后再人工修订。这能降低写作成本，但模型可能学习 teacher 的叙述习惯；而文本 CoT 是否是性能提升的必要因素，论文未单独消融。

### 6. RL 结果更像一个负面发现，而不是成熟的优化解法

HPS reward 消融中，SFT baseline 的 overall 反而最高。论文诚实呈现了这一点。对未来工作而言，关键不只是换一种 policy optimizer，而是建立能区分“朝目标靠近”和“沿可行路径前进”的过程监督或世界模型。

## 🔗 与相关工作的关系

### 与 V* / 静态图像视觉搜索相比

静态搜索在固定画布中选择 ROI 或 zoom；HVS 的旋转会改变观察，要求 agent 对尚未看到的空间作决策。H* Bench 上的性能崩塌说明两者不是同一能力的简单尺度变化。

### 与 Vision-Language Navigation 相比

VLN 评估完整移动轨迹和最终到达；HVS 只评估关键点上的搜索和方向提交。HVS 更轻、更容易使用真实数据扩展，但不测连续移动、记图、避障和执行控制。

### 与 MLLM tool use 相比

OCR、crop、zoom 等工具扩展模型对静态文件的处理；HVS 把工具调用绑定为物理含义明确的头部动作，使 tool use 进入 perception-action loop。

### 与 embodied reasoning benchmark 相比

许多具身 benchmark 集中在家庭环境或合成模拟器。H* Bench 的独特价值是交通枢纽、商场和公共机构中的密集视觉线索及社会空间规则。

## 💡 可操作的研究启示

1. **指标应分解成功来源**：分别报告目标可见性、探索效率、首次正确定位、最终对准、物理可行性和社会可行性，而不是只有终局方向成功率。
2. **路径 reward 要表达拓扑可达性**：单纯角距离不足以监督绕障和楼层连接，可考虑导航图、可行区域、关键 waypoint 或 learned world model。
3. **困难样本不能被总体均值掩盖**：RL 可能只优化视觉线索与路径一致的 easy split，因此训练和选模应按难度分层。
4. **需要跨环境反事实测试**：保持目标和路径结构不变，只替换文字、建筑风格或地理区域，可检查模型是否依赖标识语言和场景捷径。
5. **从全景到真实机器人要逐层验证**：先加入相机噪声和旋转误差，再加入平移与遮挡变化，最后评估真实头部机构，避免把模拟朝向成功直接等同于部署能力。

## 📖 关键术语

**Humanoid Visual Search（人形视觉搜索）**：局部视野 agent 通过主动旋转头部搜索目标或路径的任务。例子：在地铁站不断转头观察指示牌，最后对准正确出口方向。

**Humanoid Object Search, HOS（人形物体搜索）**：搜索并把目标物体置于中央注视区域。例子：找到货架上的指定商品并细调视角，使商品进入视野中心。

**Humanoid Path Search, HPS（人形路径搜索）**：在移动前找到通向目的地的可行方向。例子：目标在楼上时，不是朝目标直线方向提交，而是先对准可通行楼梯。

**Cephalomotor Control（头部运动控制）**：通过头部转动探索更大范围环境。例子：当前视野没有目标时向后转 120° 查看未见区域。

**Oculomotor Control（眼动控制）**：在已有视野内通过眼球运动搜索和注视细节。论文没有显式模拟眼球，而由模型对透视图的细粒度处理近似。

**Field of View, FoV（视场）**：一次观察可见的角度范围。窄 FoV 能减少全景扭曲，但要求多轮旋转才能覆盖环境。

**Foveation（中央注视/中心化）**：把目标移到视野中央高分辨率区域。例子：已经看到店铺招牌后再小角度转头，使其落入成功容差。

**Perception-Action Loop（感知—动作闭环）**：观察决定动作，动作又改变下一次观察。例子：看到向右箭头后右转，再根据新出现的楼梯决定继续转还是提交。

**Physical Commonsense（物理常识）**：对可通行性、障碍、楼层和空间结构的常识。例子：知道不能穿过玻璃墙，必须从门或走廊绕行。

**Socio-Spatial Commonsense（社会空间常识）**：公共空间的功能和行为规范。例子：知道应走斑马线，不能把员工柜台后方当作普通捷径。

**GRPO（组相对策略优化）**：同一任务采样多条轨迹，以组内相对 reward 计算 advantage 的策略优化方法。例子：在多个不同转头轨迹中，相对提高最终正确提交且格式合法的轨迹概率。

## ✅ 总结

《Thinking in 360°》的主要价值不在提出新的模型架构，而在提出一个清晰、可扩展的研究切面：用真实 360° 全景模拟头部旋转，把静态视觉搜索推进到有动作后果的主动具身搜索，并用 H* Bench 暴露现有 MLLM 的能力缺口。

论文最强的证据是：静态搜索高分并不迁移到 H* Bench；SFT 能显著建立基本搜索行为；物体搜索和路径搜索呈现完全不同的后训练上限。最需要谨慎的地方是，固定中心全景仍是完整具身世界的简化代理，HPS 的单方向指标也不能覆盖多路径与实际可达性。

对后续研究而言，最重要的结论不是“增加 GRPO 就能解决具身搜索”，恰恰相反：**当任务从找目标升级为找可行路径时，角距离和终局正确性这类简单奖励会把容易样本优化得更好，却无法稳定教会模型物理、拓扑和社会空间推理。**
