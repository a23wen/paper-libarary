## 研究背景

Apple Remote 最初是为控制一款软件而设计的。除了这只遥控器，还有什么能控制那款软件？论文图 1 把同一道题交给几种提示方法。直接回答的模型猜了 iPod。使用思维链（CoT）的模型写出了流畅的推导，却在第一步把软件认成了 Apple TV，后面列出的设备也就偏离了问题。[论文图 1](https://arxiv.org/pdf/2210.03629v3#page=2)

这道题需要两种能力。模型得先去查遥控器与软件的关系，再根据查到的软件名称追问控制方式。CoT 擅长把问题拆开，但在这个设置里，每个事实都来自模型自己的记忆。WebGPT 等工作已经让模型操作浏览器，展示了获取外部资料的可能。ReAct 追问的是，模型能否读懂刚取得的证据，并据此决定下一次操作？[论文第 1、5 节](https://arxiv.org/pdf/2210.03629v3#page=9)

## 问题与挑战

即使工具工作正常，模型也可能答错。图 1 中只执行动作的 **Act** 先查 Apple Remote，接着查 Front Row，遇到同名条目后又找到了正确的 Front Row 软件页面。它已经看到了回答所需的材料，最后却提交了 `yes`。题目问的是“用什么控制”，它回答成了“能不能控制”。如果只检查搜索是否命中，就会漏掉这个发生在答案合成阶段的错误。[论文图 1](https://arxiv.org/pdf/2210.03629v3#page=2)

交互任务还有一层难处。模型每执行一个动作，后续可见的信息就可能改变。搜索返回同名候选时，需要改写查询。打开商品页看到多个规格时，需要重新核对购买条件。长任务还要记住哪些子目标已经完成。如果模型只顾续写原来的计划，一次空搜索或一次无效动作就可能在后续步骤中反复出现。

## 核心发现 Finding

**作者的核心主张是，推理可以给行动指定目标，行动可以给下一次推理补充证据。** 在 Apple Remote 的例子中，第一次搜索确定了软件名 Front Row。第二次搜索没有直接命中，模型从候选中选了带有 `software` 限定的词条。看到新页面后，它把“软件也接受键盘功能键控制”与题目里的“除了遥控器”对应起来，提交了“键盘功能键”。Act 在这个例子里走过了相同的检索路径，差别出现在如何使用最后一段证据。[论文图 1、作者项目页](https://react-lm.github.io/)

**我的理解是，写下一句中间判断最有价值的时刻，是它能改变下一步决策的时候。** “已经知道软件名，仍缺控制方式”既记录了进度，也限定了接下来要找的证据。用同样的思路看购物任务，“已经找到合适的商品，还没选包装数量”就能阻止模型过早点击购买。回看轨迹时，可以追问哪条观察改变了哪个判断，那个判断又改变了哪个动作。

## 方法

1. **给出任务和示范。** 主实验使用冻结的 PaLM-540B。每条示范记录任务、人工写下的思路与动作，以及环境对动作的实际反馈。HotpotQA 和 FEVER 分别使用 6 条和 3 条示范。遇到新问题时，模型可以看到题目或待核验陈述，支持段落需要自己寻找。
2. **允许模型先写一句中间判断。** 作者把原有动作集合扩展为“环境动作或自然语言思考”。模型生成的 `Thought` 会进入后续上下文，只改变模型下一步读到的历史。它可以记录一个已确认的事实、一个尚缺的条件，或者一次搜索失败后应采用的新词条。
3. **执行动作，接收观察。** 问答环境提供三个动作。`search[实体]` 命中时返回词条开头五句，未命中时给出最多五个相似条目。`lookup[字符串]` 在当前页定位下一条含该字符串的句子。`finish[答案]` 提交答案并结束。工具返回的 `Observation` 来自外部环境，可供模型校正上一步的猜测。
4. **按任务决定什么时候再想。** 知识任务的示范在每次动作前写出思路。ALFWorld 和 WebShop 的轨迹更长，示范只在拆解目标、遇到意外或切换子目标时插入思考。模型可以连续执行多个动作，例如选口味、选数量、点击购买。[论文第 2–4 节](https://arxiv.org/pdf/2210.03629v3#page=3)

## 实验与结论

### 知识任务中，检索改善了什么？

HotpotQA 要跨维基百科段落回答问题，用答案精确匹配率（EM）计分。FEVER 要判断一项陈述得到支持、遭到反驳，还是证据不足，用分类准确率计分。下表是论文表 1 的 PaLM-540B 提示实验，数字单位均为 %。[论文表 1](https://arxiv.org/pdf/2210.03629v3#page=5)

| 提示策略 | HotpotQA EM | FEVER 准确率 |
|---|---:|---:|
| 直接回答 | 28.7 | 57.1 |
| CoT（只推理） | 29.4 | 56.3 |
| Act（只行动） | 25.7 | 58.9 |
| ReAct | 27.4 | 60.9 |
| CoT-SC（采样 21 条思维链后投票） | 33.4 | 60.4 |
| CoT-SC → ReAct | 34.2 | **64.6** |
| ReAct → CoT-SC | **35.1** | 62.0 |

加入推理后，ReAct 在两项任务上都超过使用相同工具的 Act。与只推理的 CoT 相比，ReAct 在 FEVER 高 4.6 个百分点，在 HotpotQA 低 2.0 个百分点。表中箭头表示**有条件地切换**。先检索时，HotpotQA 在 7 步、FEVER 在 5 步内未能提交答案才转向 CoT-SC。先投票时，得票最多的答案若仍未达到半数，才启动 ReAct。[论文第 3.2 节](https://arxiv.org/pdf/2210.03629v3#page=5)

错误分析解释了两种策略为什么互补。作者为 ReAct 和 CoT 各抽取 50 条 EM 正确、50 条 EM 错误的 HotpotQA 轨迹，共 200 条。在各自答错的样本中，CoT 有 56% 被归为幻觉，ReAct 对应为 0%。推理错误在 ReAct 中占 47%，在 CoT 中占 16%。反复执行相同搜索也计入推理错误。另有 23% 的 ReAct 错例源于检索没有提供有用材料。即使只看答对的样本，ReAct 仍有 6% 的轨迹含有虚构内容。**这些比例描述的是人工抽查的分组样本**，也说明一次正确的最终回答可能掩盖中间错误。[论文表 2](https://arxiv.org/pdf/2210.03629v3#page=6)

### 在长任务中，思考应该插在哪里？

**ALFWorld** 用 134 个未见过的文字家务游戏测试六类任务。每类从三条示范中有序选两条，形成六套提示。Act 使用相同轨迹并删去思考。ReAct 在六套提示上的总体成功率平均为 **57%**，最佳为 **71%**。Act 的最佳成绩为 45%，模仿学习基线 BUTLER 的八次试验最佳为 37%。因此摘要中提高的 **34 个百分点**来自 71% 与 37% 的比较。把思考改成更密集、内容限于当前目标与子目标的反馈后，ReAct-IM 的平均成功率为 48%，最佳为 53%。这项消融同时改变了思考的内容与频率，单靠它无法判断哪一个因素贡献更大。[论文表 3](https://arxiv.org/pdf/2210.03629v3#page=8) · [附录 B.2](https://arxiv.org/pdf/2210.03629v3#page=15)

**WebShop** 的 500 条测试指令更接近日常选择。附录里的用户要买 16 包装、苹果肉桂味、低于 50 美元的冻干香蕉片。Act 点开标价 85 美元的商品便下单，得分 0.125。ReAct 发现另一条搜索结果虽然标题写着 6 包装，详情页却提供口味与包装选项，于是分别选中苹果肉桂味和 16 包装，得满分。打开详情页后逐一核对选项，正是这一单中值得停下来推理的时刻。[附录 D.3，表 10](https://arxiv.org/pdf/2210.03629v3#page=31)

汇总到整个 WebShop 测试集，单示范 ReAct 的平均属性得分为 **66.6**，满足全部要求的订单占 **40.0%**。Act 的两个数字为 62.3 和 30.1%，模仿学习基线为 59.9 和 29.1%，人类专家为 82.1 和 59.6%。作者观察到，人类更常改写查询，并查看多个候选商品。找到一件看上去合适的商品后要不要继续探索，仍是模型的弱点。[论文表 4](https://arxiv.org/pdf/2210.03629v3#page=8)

### 小模型能学会这种交互方式吗？

作者还在 HotpotQA 上用模型生成、最终答案正确的 3,000 条轨迹做微调。只给少量示范时，ReAct 在 8B、62B 两个规模上均是四种单独格式中表现最差的。微调后，ReAct 在两种规模上都排到第一。8B 微调模型超过 62B 的四种单独提示，62B 微调模型也超过 540B 的四种单独提示。这项 HotpotQA 实验表明，较小模型也能从轨迹中学会何时检索以及怎样使用返回结果。图 3 的比较范围是直接回答、CoT、Act、ReAct 四种格式。[论文图 3](https://arxiv.org/pdf/2210.03629v3#page=7)

## 关键术语

| 术语 | 含义与例子 |
|---|---|
| Thought（思考） | 模型写进当前轨迹的一句中间判断。例如“已定位到 Front Row，还需查它接受哪些控制方式”。 |
| Action（动作） | 环境能够执行的命令。例如打开一个具体词条、选择包装规格，或提交最终答案。 |
| Observation（观察） | 环境对动作的返回。例如搜索给出的相似词条，或商品页真正提供的规格列表。 |
| Trajectory（轨迹） | 从任务输入到结束的完整交互记录。沿它回看，可以定位模型从哪次搜索开始偏离问题。 |
| Self-consistency（自一致性） | 对同一问题采样多条推理路径，按最终答案投票。论文用投票的集中程度决定是否需要外部检索。 |

回看一个 ReAct 系统，可以从一条失败轨迹入手，找到**第一次本该改变下一步动作的观察**。若搜索已经给出正确页面而模型仍答错，应该检查证据提取和答案合成。若一直取不到新材料，就该检查查询改写和退出条件。这两种错误在最终分数上看起来一样，却需要改不同的环节。
